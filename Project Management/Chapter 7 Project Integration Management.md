# Develop Project Charters
## Project Charters
- A project charter is a formal, high-level document that officially authorizes the existence of a project, outlining its purpose, goals, scope, and key stakeholder.
- Developing Project Charter - part of Project Initiation phase
- project charter authorize PM to start the project and to use organizational resources as required.
- Document that formally recognizes the existence of a project and provides direction on project objectives and management
- charter serves as an agreement contract between project sponsor and project team documenting the projects.
- It should address following
	- Requirements that satisfy customer, sponsor, and other stakeholder needs, wants and expectation
	- business needs, high level, project description or product requirements that project is undertaken to address
	- project purpose or justification
	- assigned project manager and authority level
	- summary milestone schedule
	- stakeholder influences
	- functional organization and their mode of participation
	- organizational, environment and external assumptions/constraints
	- business case justifying the project, including Return on investment
	- summary budget

## Tools and Techniques
1. Focus on broad organizational needs
	- Need: do people in the organization agree that the project NEEDS to be don?
	- Funding: is the needed FUNDING secure for the project?
	- Will: is there a strong WILL to make the project succeed?
2. Categorize IT projects
	- one categorization is done whether the project addresses a problem, an opportunity or a directive
3. Perform net present value or other financial analysis
	- three primary methods for determining projected financial value of projects
	1. NPV analysis
		- NPV is the difference between the present value of cash inflow and the present value of cash outflows over a period of time
		- all expected future cash inflows and outflows are depreciated to present point in time
		- if NPV > 0, Accept .
		- if NPV < 0, reject
		- if NPV = 0, remain indifferent.
	2. ROI
		- calculated by subtracting the project costs from the benefits and then dividing by the costs
		- ROI = net income / cost of investment
	3. Payback Analysis
		- mathematical methodology to determine the payback period for an investment
		- the payback period is how long it will take to pay off the investment
		- break even poitn => net income = 0, profit = loss
		- must be less
4. Use a weighted scoring model
	- total weighted score = sum of all weight of each attribute of a project * numerical value of that attribute
	- lets say, project A has profit potential rating of 5, marketability of 4, ease of production = 4,
	- project b has profit potential at 5, marketability of 3, ease of production = 4
	- say, profit potential has weight 5, marketability 3, ease of production = 1
	- then for A, total score = 41
	- for B, total score = 38
	- choose A
5. Implement a balanced scorecard

## Project Scope Management
- scope refers to all the work invvolved in creating the products of the project and the process used to create them
- project scope management includes the processes involved in defining and controlling what is or is not included in the project
- the project team and stakeholders must have the same understanding of what products will be produced as a result of project and what proceses will be used in producing them
### Project Scope
- scope
	- the sum of the products, services and results to be provided as a project
- Project scope
	- the work that must be done in order to deliver a product, services, or result with the specified features and functions
	- completion measured against the project plan
	- the features and functions that characterize a product service or result
	- completion is measured against the product requirements.
### Project Scope Management Process
- initiation: beginning a project or continuing to the next phase
- scope plannigng: developing documents to provide the basis for future project decisions
- scope definition: subdividing the major project deliverables into smaller, more manageable components
- scope verification: formalizing acceptance of teh project scope
- scope change control: controlling changes to project scope.
### Sample Scope Management Plan
#### Preparing Scope Statement
- the preliminary scope statement will provide the basis for preparing more detailed scope statements
- the scope statement needs to be reviewed with key stakeholders, especially the project sponsor, potential suppliers, and users of the project deliverables.
- follow corporate templates when available and be sure to have expert input in defining the scope
- since the scope statement becomes more detailed and therefore longer as the project progresses, limit the length and complexity of the scope statement by placing details in attachments, such as product descriptions, specifications, corporate standarads, etc.
- each version of the scope statement must be clearly labeled and dated to ensure that everyone sues the most recent eversion.
- changes and additions will be highlighted and communicated to the appropriate personannel.
- the scope statement will be available on the password protected project web site

# Work Breakdown Structure (WBS)
- process of systematically breaking down the major project work into smaller, more manageable components and sub components in hierarchical order.
- a work package is a task at the lowest level of the WBS.
	- e.g., gantt chart.
## Adv
- Planning can be performed easily
- cost and budgets can be established
- schedules can be established
- responsibility can be assigned to each activity
- can be used to analyze risk of each activity
## Create WBS
- Defines work (what)
- identify time to complete a work package (how long)
- identify a time-phased budget to complete a work package (cost)
- identify resources needed to complete a work package (how much)
- identifies a person responsible for units of work (who)
- identifies monitoring points (milestones) for measuring success
## Levels of WBS
-> Total Program
	-> Project
		-> Task (activity)
			-> Sub-tasks
				-> Work Packages
					-> Level of efforts
## Approaches to Developing WBS
1. Using Guidelines
	- some organizations, provide guidelines for preparing WBSs
2. The analogy approach
	- review WBSs of similar projects and customize it to your project
3. The top down approach
	- start with the largest items of the project and break them down
4. the bottom up approach
	- start with the specific items of the project and break them down
5. Mind Mapping approach
	- mind mapping is a technique that uses branches radiating out from a core idea to structure thoughts and idea
